# Архитектура V1.0 (утверждена)

## Принципы
1. **Local-first.** После первой загрузки всё работает без интернета. Сеть нужна только будущим: синхронизации, ИИ, внешним сервисам.
2. **План и факт — разные сущности.** `plannedItems`/`plannedSets` (план) и `foodLogs`/`setLogs` (факт). Рекомендации и прогрессия опираются на факт.
3. **Версии программы — неизменяемые снимки.** Изменение = новая версия + запись в `planChanges` с причиной и цифрами.
4. **Движки детерминированные и чистые.** Время, id, случайность приходят через порты/параметры.
5. **ИИ только через предложения:** контекст → ИИ → JSON → Zod → доменный валидатор → черновик → подтверждение → новая версия. ИИ не пишет в базу.

## Решения, принятые на согласовании
- Версии как документы-снимки (откат и история проще).
- Синхронизация по `updatedAt` + `deletedAt`. **Last-write-wins не считается универсально безопасным:** при появлении второго устройства стратегию конфликтов пересматриваем (журналы объединяются, планы — по явным правилам).
- Каталог: ~80 упражнений, приоритет — качество тегов и замен, а не количество.
- Разовый импорт Excel — в V1.0: Excel → нормализация → preview → валидация → импорт. До подтверждения данные не меняются, нераспознанное показывается отдельно, существующее не перезаписывается.
- **Прогрессия не привязана только к exerciseId.** Контекст: упражнение + вариант + диапазон повторений (+ оборудование). Ключ: `progressionKey()`; хранится в `plannedSets.contextKey` и `setLogs.contextKey`.
- **RIR участвует в алгоритме** `nextPrescription`, не только в статистике (этап 2/7).
- **Боль не блокирует упражнение автоматически:** событие → предупреждение/остановка → безопасные альтернативы → при повторении proposal на замену. Диагнозов нет.
- **Расписание по дням недели:** `profile.trainingSchedule`. Перенос пропущенной тренировки меняет только `plannedSessions.plannedDate` (статус `moved`, `originalDate`), новую версию не создаёт.

## Что где
- Сущности и схемы: `packages/domain/src/model/*` (реестр хранилищ: `registry.ts`).
- Порты: `packages/domain/src/ports/index.ts`.
- Утилиты: даты без часового пояса (`LocalDate`), `progressionKey`.
- Валидатор каталога: `validators/seedCatalog.ts`.

## Правила хранения
- `id`: UUID v7 для данных пользователя, slug (`ex_…`/ключ) для каталога.
- Все записи: `createdAt`, `updatedAt`, `deletedAt` (мягкое удаление), `deviceId`. Адаптер хранилища сам ставит `updatedAt`.
- Единицы: кг, см, г. Даты дней — `LocalDate` (`YYYY-MM-DD`), моменты — ISO 8601 со смещением.
- RIR: 0–4, где 4 = «4 и больше».
- Версия схемы: `SCHEMA_VERSION` (поднимается вместе с миграцией Dexie).
